IntiHA v0.2.5 - Home Assistant Bluetooth active discovery hotfix
===============================================================

This patch is based on the IntiHA 0.2.4 source supplied in this conversation.
It improves DISCOVERY, not the separate Bond GATT peer-disconnect problem.

Option A - from an existing v0.2.4 Git checkout:
  git apply --check IntiHA-v0.2.5.patch
  git apply IntiHA-v0.2.5.patch
  git add -A
  git commit -m "Request actual Home Assistant active Bluetooth scans"
  git push

Option B - manually copy the paths under files/ to corresponding repository
paths, preserving directories. Files under files/ contain only files that
change; they are not a complete repository. Do not copy APPLY_PATCH.txt or
this .patch file into custom_components.

Release: tag v0.2.5 after CI checks and publish the GitHub draft release so
HACS receives the new version and release notes.

Installation:
  1. HACS -> IntiHA -> Redownload/update the integration to 0.2.5.
  2. Restart Home Assistant Core.
  3. The existing IntiHA Engine app v0.2.4 may remain running: there is no
     bridge API change. The app metadata is bumped to 0.2.5 for release
     consistency, but rebuilding/reinstalling it is NOT required here.
  4. With the second device advertising, press Search devices. The HACS
     integration now requests a real on-demand active scan from HA.

Notes:
  - Device compatibility still depends on the Buttplug protocol definitions.
    If Home Assistant's Bluetooth map sees the second device but IntiHA does
    not, capture its model/name and advertisement data for protocol diagnosis.
  - A discovered device is not necessarily connected. The Bond's 9-attempt
    ESP_GATT_CONN_TERMINATE_PEER_USER failure remains a separate problem.
  - AUTO scanners receive the sweep; explicitly PASSIVE scanners stay passive.

Local validation:
  4 active-scan coordinator tests, 33 existing BLE transport tests passed.
  Syntax, patch-apply, and metadata checks passed. No physical hardware test.
